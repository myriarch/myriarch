### Added

- **Installation from the server on Windows.** `install-windows.ps1 -Server <url> -TokenFile <file>` does what the Linux installer does ([ADR-0046](docs/adr/0046-host-installation-from-the-server.md)): it asks `POST /api/v1/install/plan` (the token only as a request header), reads the plan strictly as data (known keys only, each value against a pattern, at most 64 lines and 8 KiB, URLs of the origin of `-Server` only, https only, redirects only to https on the same origin, nothing evaluated as code), downloads collector and supervisor with the install grants of the plan and verifies them by SHA-256 and their Sigstore bundle against an identity, issuer and version that it builds itself, with the `myriarch-updater.exe` of the installer bundle as verifier, so the host needs no `cosign.exe`. New parameters are `-Server`, `-Fleet` and `-PlanWait`; the error codes `plan_failed`, `plan_invalid`, `plan_rejected` and `plan_unavailable` apply as on Linux, next to `https_required`, `conflicting_install`, `supervisor_missing` and `language_mode_unsupported`. The Windows commands that the server renders run unchanged with the script (`-Server`, `-TokenFile`, `-Fleet`, `-CollectorVersion`, `-Insecure` and the site options). The command sets the execution policy for its PowerShell process only (never `Bypass`, no change of the machine or user policy) and reports a policy from Group Policy instead of working around it. The working directory of the installer is made below `%ProgramFiles%` with a DACL for SYSTEM and the administrators before the first download. The certificate of the server is checked against the certificate store of the machine. The Windows files are not Authenticode-signed: `AllSigned` blocks them and App Control needs a hash rule for each release. See [Connect a host](docs/tasks/connect-a-host.md#one-command-install-a-windows-host-from-the-server) and [Installing a host from the server](docs/operations/troubleshooting.md#installing-a-host-from-the-server).
