### Added

- **Host end-to-end test on Windows.** The job `windows` of `host-e2e.yml` runs `scripts/host-e2e/windows.ps1 one-command` on a fresh `windows-2025` runner, in Windows PowerShell 5.1 and in PowerShell 7 at the same time. It builds `myriarchd` (embedded PostgreSQL), `myriarch-updater` and `myrctl` from the commit, serves the installer bundle (zip) from a directory by the development server, creates an enrollment token at run time, renders the command through `POST /api/v1/install/commands` and runs it unchanged in an administrator session. It checks a healthy agent in the fleet `windows-hosts` at the target version of that fleet, the two services (the supervisor under `NT SERVICE\otelcol-supervisor`, the updater as LocalSystem), the ACL of the registry key that holds the token and of the data directories, a configuration rollout, a version update through the updater with a killed collector (rollback by the updater) and the retry, and `install-windows.ps1 -Uninstall -Purge` with the proof that no service, file, registry key, process, listener or working directory is left. The script refuses to run unless `CI=true` and `HOST_E2E=1` are set, on Windows, elevated, on a GitHub-hosted runner and on a host without an earlier installation; the throwaway CA is in the certificate store of the machine only while the scenario runs; the token is masked in the log and the upload takes an allow-list of scrubbed files, never the token file or the rendered command. The path filter names the Windows installer, `deploy/updater/windows/**`, `deploy/supervisor/windows/**` and `deploy/windows/**`, and the input `release_tag` also runs the scenario against the published bundle of a release. The job runs in CI only; the support level of Windows stays "experimental" until it is green. `ci/tests/workflow-artifacts-check.py` checks the shape of both jobs and `ci/tests/host-e2e-test.sh` the helpers and the guard under `pwsh`.
