# Job-level write permissions that the workflow policy check (ci/check-workflows.py, rule R3) allows.
#
# Every workflow has `permissions: contents: read` at the top. A job may ask for more only when it is listed here, one
# line per scope in the form
#
#   <workflow file> <job id> <scope>
#
# for example `deploy.yml publish pages`. Each line needs a review of the job: which scope, why, and either that the job
# does not run code of a pull request or why the scope is harmless there. An entry is added only together with that review.

# CodeQL (.github/workflows/codeql.yml). The job `analyze` uploads the SARIF results of the analysis to code scanning, which needs
# security-events: write; contents is read-only. The job analyses the code of every pull request to main. The token of a pull
# request from a fork is read-only whatever the workflow asks for (GitHub still lets code scanning upload the results of such a
# run). A Dependabot pull request does receive the scope: the token of Dependabot is read-only by default, and the permissions key
# of the job raises it. The scope writes code scanning alerts and also dismisses them; it gives no access to contents, packages,
# releases or deployments. That is harmless because the steps of the job compile the code and run none of it (no test, no package
# installation, no generator) and the job has no secret and no other scope; a branch of this repository needs write access to the
# repository anyway.
codeql.yml analyze security-events

# OpenSSF Scorecard (ADR-0033; .github/workflows/scorecard.yml, the shape is fixed by rule R12). The job `analysis` runs on pushes
# to main and on a schedule, never on a pull request, and has no secret. security-events: write uploads the findings to code
# scanning; id-token: write gives ossf/scorecard-action the OIDC token that authenticates the published result at the Scorecard API.
# The token is bound to this workflow (scorecard.yml on refs/heads/main), which no verification of a release accepts (ADR-0029).
# The job has no write access to contents, packages or releases.
scorecard.yml analysis security-events
scorecard.yml analysis id-token

# Release workflow (ADR-0035; .github/workflows/release.yml, shape fixed by rule R13). It runs only for a pushed v* tag, never
# for a pull request, and holds no secret in v0.1.0. Every job below needs the job sign-windows (approval 1, the environment
# release) in its chain of needs and takes only artifacts of the same run, downloaded by ID and checked against the SHA-256 that
# the producing job reported; build code (go, node, pnpm, goreleaser, make) runs only in jobs with contents: read, and these
# jobs execute only the signing tool set (cosign, crane, gh), which is built on a runner of its own. A gate is passed once per
# run, not once per attempt: "Re-run failed jobs" runs a failed job below again without asking for approval 1 again.
#
# sign-blobs signs checksums.txt keyless (cosign sign-blob) and attests the build provenance of its 39 subjects (actions/attest):
# id-token: write mints the OIDC token of release.yml at the tag (the signing identity of ADR-0029), attestations: write stores
# the attestation. No contents, packages or release access.
release.yml sign-blobs id-token
release.yml sign-blobs attestations
# push-images pushes both images by digest only (no release tags), signs them (cosign sign --recursive) and attaches the
# provenance and SBOM attestations in ghcr.io, strictly in sequence. packages: write is limited by GitHub to the packages of
# this repository; id-token and attestations as above. No contents or release access.
release.yml push-images id-token
release.yml push-images attestations
release.yml push-images packages
# draft creates the draft release of the tag with the verified-to-be file set; contents: write is the only scope that the
# Releases API accepts for that. A draft is invisible to the public and stays editable until finalize. The job runs before
# approval 2 and has no environment: approval 2 stops finalize only, so draft runs nothing but the signing tool set and
# ci/release scripts (docs/security/model.md).
release.yml draft contents
# finalize runs after approval 2 (environment release): it checks that the draft still holds exactly the verified files
# (GitHub's asset digests), sets the image tags with crane and publishes the release, which becomes immutable.
release.yml finalize contents
release.yml finalize packages
